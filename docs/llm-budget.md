# AI(엑사원) 사용량 통제 설계 (초안)

> 상태: **초안 — 리뷰 대기.** 기준: `docs/api-contract.md`, `docs/db-schema.md`, `AGENTS.md` Section 7.
> 목표: (1) 엑사원 제공자의 호출 한도를 넘지 않고, (2) 한 사용자가 한도를 독점하지 못하게 하며, (3) 한도가 막혀도 **서비스의 코어(스캔·보안 검증·QR)는 계속 동작**하게 한다.

---

## 0. 전제와 미확인 사항

- 공식 문서 기준(조사 보고): 한도 초과 시 **429**, 응답 헤더 `x-{second|minute|day}-rate-limit`, `…-remaining`, `retry-after`, `retry-after-ms`.
- **한도의 구체적 수치(초·분·일 단위, 토큰 한도 유무)는 문서에서 확인되지 않았다.** API 콘솔에서 확인해야 하며, 이 문서의 숫자는 모두 **설정값**(`[vars]`)으로 두고 제공자 한도의 일정 비율(안전선)로 계산한다.
- 2026-11-09에 무료로 공개된 직후라 한도·무료 기간이 바뀔 수 있다. 값 변경에 코드 수정이 필요 없도록 한다.
- 아래 "초기값"은 **제안**이다. 제공자 실제 한도와 목표 사용자 수가 정해지면 다시 계산한다.

## 1. 원칙

1. **코어는 AI 없이 동작한다.** 보안 등급, 제품 조회, QR 생성은 코드가 처리하므로 AI 통제가 실패해도 핵심 기능은 유지된다 (AI는 설명·대화 담당).
2. **호출을 줄이는 것이 통제보다 먼저다.** 캐시·템플릿으로 불필요한 호출을 없앤다.
3. **빨리 실패한다(fail fast).** 큐에 쌓거나 오래 재시도하지 않고, 한도 상태면 즉시 템플릿 문구로 대체한다 (Workers 요청 시간·사용자 대기 모두 보호).
4. **서버가 거부하기 전에 사용자에게 보여 준다.** 응답마다 남은 사용량을 내려 UI가 미리 안내한다.

## 2. 1차 방어: 호출 자체를 줄이기

| 방법 | 내용 | 효과 |
| --- | --- | --- |
| 호출 생략 | 제품 미적중, 비-URL QR, 체크디지트 오류, 쿼터 초과 시 코드 템플릿 사용 | 해당 케이스 호출 0 |
| **narration 전역 캐시** | `narration_cache`(D1)에 저장. 키 = `sha256(카드 타입 + 프롬프트 버전 + 서술에 쓰이는 facts)`. 같은 상품·같은 보안 신호 조합은 **전체 사용자가 재사용** | 인기 상품·반복 신호는 호출 1회만 |
| 서술 입력에서 도메인 제외 | 보안 카드 서술은 `grade + signal code 목록`만 입력(도메인은 facts로 별도 표시) → 캐시 적중률 상승 | 보안 카드 호출 대폭 감소 |
| 입력 토큰 절감 | 사용자 입력 500자 제한, 채팅 맥락은 최근 8개 메시지, **카드 메시지는 facts 요약만** 전달(카드 JSON 전체 금지) | 호출당 비용 감소 |
| 출력 상한 | `max_tokens`: narration 300, chat 600. `reasoning_effort=low` | 지연·비용 상한 |
| 중복 제출 방지 | 같은 세션에서 동일 입력이 10초 안에 다시 오면 이전 응답 재사용 | 연타·재시도 차단 |
| 보안 서술 템플릿화(선택) | `signal code → 고정 문구` 조합으로 충분하면 보안 카드는 엑사원 없이 템플릿만 사용, 엑사원은 채팅 질문에만 | 가장 확실한 절감 (UX 차이 확인 후 결정) |

## 3. 한도 계층

카운터 단위는 "엑사원 API 호출 1회"다. 채팅과 스캔 서술을 분리한다. 스캔 서술은 핵심 기능이라 사용자에게 한도로 보이지 않고, 한도에 걸리면 **조용히 템플릿으로 대체**한다.

| 범위 | 구분 | 윈도우 | 초기값(제안) | 초과 시 |
| --- | --- | --- | --- | --- |
| 전역 | 모든 호출 | 분 | 제공자 분당 한도 × 안전선(0.8) | 해당 요청 AI 생략 / 채팅은 `QUOTA_EXCEEDED` |
| 전역 | 모든 호출 | 일(KST) | 제공자 일 한도 × 안전선(0.8) | 4절 단계 L2~L3 |
| 세션 | 채팅 | 분 / 일 | 5회 / **20회** | 429 `QUOTA_EXCEEDED` (UI에 재개 시각) |
| 세션 | 스캔 서술(캐시 미스) | 일 | 60회 | 템플릿으로 대체 (오류 아님) |
| IP(해시) | 채팅 / 스캔 서술 | 일 | 세션 한도의 3배 | 위와 동일. 공유 IP(CGNAT) 오탐을 줄이려 배수를 둔다 |
| IP | 신규 세션 생성 | 시간 | 20회 | 429 `RATE_LIMITED`, Turnstile 트리거 |

**세션 일 한도 산정 방식:** `세션 채팅 일 한도 ≈ (전역 일 한도 × 안전선 × 채팅 몫) ÷ 목표 일일 활성 사용자 수`. 채팅 몫은 기본 0.5(나머지는 스캔 서술용). 목표 사용자 수와 제공자 일 한도가 정해지면 이 식으로 확정한다.
- "1인당 사용량이 너무 많은" 사용자는 세션 한도로 막고, 세션을 계속 새로 만드는 우회는 **IP 한도 + 세션 생성 제한**으로 막는다.

## 4. 구현 방식: D1 원자 카운터

KV는 값이 늦게 반영되고(최종 일관성) 쓰기 한도가 작아 정확한 카운터에 맞지 않고, Workers Rate Limiting 바인딩은 데이터센터별 근사치라 **제공자 한도를 지키는 전역 카운터**로는 부정확하다. D1은 강한 일관성이라 한 번의 SQL로 "한도 이하일 때만 증가"를 원자적으로 처리할 수 있다.

```sql
CREATE TABLE llm_usage (
  scope        TEXT    NOT NULL,   -- 'global:min' | 'global:day' | 'session:chat:min' | 'session:chat:day'
                                   -- | 'session:scan:day' | 'ip:chat:day' | 'ip:scan:day' | 'ip:newsession:hour'
  key          TEXT    NOT NULL,   -- 'all' | session id | SHA-256(IP) 앞 16자
  window_start INTEGER NOT NULL,   -- 윈도우 시작 epoch ms (일 윈도우는 KST 자정 기준)
  count        INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (scope, key, window_start)
);

-- 획득: 한도 미만일 때만 증가한다. 한도에 도달했으면 행이 반환되지 않는다.
INSERT INTO llm_usage (scope, key, window_start, count) VALUES (?1, ?2, ?3, 1)
ON CONFLICT (scope, key, window_start) DO UPDATE SET count = count + 1 WHERE count < ?4
RETURNING count;
```

- **획득 순서:** 세션 → IP → 전역. 앞 단계는 성공했는데 뒤 단계에서 거부되면 앞에서 올린 카운트를 되돌린다(`count = count - 1`, 최선 노력).
- **호출 실패 환불:** 엑사원 호출이 429·5xx·타임아웃으로 실패하면 세션·IP 카운터는 환불하고 전역 카운터는 유지한다 (제공자 한도는 이미 소모됐을 수 있음).
- **정리:** 매일 Cron에서 이틀 지난 윈도우 행을 삭제한다. IP는 해시로만 저장하고 원문을 남기지 않는다.
- **쓰기량:** 호출 1회당 최대 3~5행 쓰기. 제공자 한도가 일 수천 회 수준이면 D1 무료 쓰기 한도(일 10만 행)로 충분하다. 일 3만 회를 넘으면 Durable Object로 이전을 검토한다.

## 5. 제공자 응답에 대한 대응

| 상황 | 대응 |
| --- | --- |
| 응답 헤더 `…-remaining` ≤ 한도의 10~20% | 전역 상태를 L1(압박)으로 전환 (KV `llm:state`, TTL 60초 — 상태 변경 시에만 기록) |
| **429** | `retry-after(-ms)`를 존중해 `pause_until = now + retry_after`(최소 5초, 최대 5분) 설정. 이 시간 동안 AI 호출 없이 템플릿으로 응답. **사용자 경로에서는 재시도하지 않는다** |
| 5xx·타임아웃 | 타임아웃 10초(스캔 서술 8초). 연속 3회 실패 시 30초간 호출 중단(서킷 브레이커). 재시도는 서술 생성에 한해 **최대 1회** |
| 401/403 (키 오류·만료) | 즉시 L3(AI 전체 중단) + 오류 로그. 사용자에게는 일시 중단 문구 |
| 제공자 초당 한도가 낮은 경우 | `global:sec` 카운터를 추가하고 초과 시 큐잉 없이 템플릿 대체 |

## 6. 단계적 축소 (Degradation Ladder)

| 단계 | 진입 조건 | 동작 | 사용자에게 |
| --- | --- | --- | --- |
| **L0 정상** | - | 모든 AI 기능 | - |
| **L1 압박** | 전역 일 사용량 ≥ 70% 또는 분 단위 remaining ≤ 20% | 채팅 세션 한도 절반, 스캔 서술은 **캐시 적중 시만** 사용(미스는 템플릿) | "AI 설명이 일부 제한돼요" 배너 |
| **L2 보호** | 전역 일 사용량 ≥ 90% 또는 429 수신 | **채팅 중단**(`QUOTA_EXCEEDED` + 재개 시각), 스캔은 facts + 템플릿 | 입력창 비활성 + 재개 시각, 스캔은 계속 가능 안내 |
| **L3 차단** | 일 한도 100% 또는 키 오류 | AI 호출 전부 중단 | 스캔·보안·QR은 정상 |

- 하위 단계 복귀는 조건 해소 후 자동(지연 60초로 깜빡임 방지).
- **스캔·보안 검증·QR 생성은 어떤 단계에서도 중단하지 않는다.**

---

## 7. 사용자에게 보이는 것

- 모든 `/api/scan`·`/api/chat` 응답에 `quota: { used, limit, resets_at, degraded }`를 포함한다 (`api-contract.md` 참조).
- UI: 채팅 입력창 근처에 "오늘 AI 대화 N/20" 표시, `degraded=true`면 배너, 한도 도달 시 입력 비활성과 재개 시각(KST 자정) 안내.
- 스캔 서술이 템플릿으로 대체돼도 오류로 보이지 않게, 카드 하단에 "AI 설명은 잠시 제공되지 않아요" 정도의 작은 문구만 둔다.

## 8. 남용·과다 사용 대응

- **세션 생성 제한:** IP당 시간당 20회. 초과하거나 전역 상태가 L1 이상이면 신규 세션에 **Turnstile** 요구 (`api-contract.md` 열린 질문 3: 평소에는 도입하지 않고 이 조건에서만 켠다).
- **반복 한도 도달 IP:** 하루 3회 이상 한도에 걸린 IP는 24시간 쿨다운(KV 차단 목록, 수동 해제 가능).
- **상위 사용자 모니터링:** 일 집계에서 사용량 상위 세션·IP를 로그로 남기고 주기적으로 확인한다. 호출당 `usage`(토큰) 합계도 집계한다.
- **알림:** 전역 일 사용량 70%·90% 도달 시 로그 경고(구현 단계에서 알림 채널 선택).
- 노출 범위 자체가 가장 큰 통제다: 초기에는 **링크를 아는 사람 한정(비공개 베타)** 으로 시작하면 한도 위험이 크게 줄어든다.

## 9. 설정값 (`[vars]` 제안)

| 이름 | 기본(제안) | 설명 |
| --- | --- | --- |
| `EXAONE_RPM_LIMIT` | 콘솔 확인 후 입력 | 제공자 분당 한도 |
| `EXAONE_RPD_LIMIT` | 콘솔 확인 후 입력 | 제공자 일 한도 |
| `LLM_SAFETY_RATIO` | `0.8` | 전역 한도 안전선 |
| `LLM_SESSION_CHAT_PER_MIN` | `5` | 세션 채팅 분당 |
| `LLM_SESSION_CHAT_DAILY` | `20` | 세션 채팅 일 |
| `LLM_SESSION_SCAN_DAILY` | `60` | 세션 스캔 서술 일 |
| `LLM_IP_MULTIPLIER` | `3` | IP 한도 = 세션 한도 × 배수 |
| `LLM_TIMEOUT_MS` | `10000` | 호출 타임아웃 (스캔 서술은 8000) |
| `LLM_NARRATION_MAX_TOKENS` / `LLM_CHAT_MAX_TOKENS` | `300` / `600` | 출력 상한 |

`db-schema.md`의 `EXAONE_DAILY_CALL_LIMIT`는 위 `EXAONE_RPD_LIMIT` × `LLM_SAFETY_RATIO`로 대체한다.

## 10. 열린 질문 (리뷰 요청)

1. **제공자 실제 한도:** 초/분/일 단위 수치와 토큰 한도 유무, 무료 기간. 콘솔에서 확인한 값이 필요하다.
2. **목표 사용자 규모:** 일일 활성 사용자 수 추정치(초기 비공개 베타면 수십 명 수준). 세션 한도 산정에 쓴다.
3. **공개 범위:** 처음부터 공개 URL로 낼지, 링크 공유 한정 베타로 시작할지.
4. **보안 카드 서술 템플릿화**(2절 마지막 행)를 Phase 1에 적용할지.
